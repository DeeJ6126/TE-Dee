# 怎样让 TE-KG 更符合 Scientific Data

基于 2026-09-02 的官方资料，暂按 **Data Descriptor** 文体讨论。以下是投稿定位建议，不是论文初稿，也不保证接收。数据库基本建设与投稿操作不在这里展开。

## 核心定位

**少证明“我们做了一个功能丰富的网站”，多证明“我们交付了一份经过可靠整理、具有新增价值、别人能够复用的数据”。** 网站是访问途径，不应抢走数据工作的主线。

期刊审稿关注技术质量、描述完整性和复用价值，不按预期影响力评价；二次数据尤其要说明相对于源数据新增了什么。[官方审稿标准](https://www.nature.com/sdata/policies/for-referees)。

## 最值得投入的五件事

1. **讲清整合的新增价值，而不是堆来源名称。** 对 TE-KG，可以核实并突出身份统一、证据追溯、多来源关联及 TE–Variant–Gene–tissue 对照。关键是读者拿到的结构化产出，比逐个访问原数据库多完成了什么。不要只把“来源多、条目多、页面多”当贡献。
2. **把最容易出错的环节作为技术验证重点。** 例如文献抽取是否忠实、实体映射是否准确、基因组坐标是否一致、eQTL 重叠是否可重现。能支持质量判断的抽查设计、错误类型和适用范围，比截图或“运行成功”更有说服力。这里是建议核对的证据，不代表这些验证已经完成。
3. **明确“关联”的边界。** 位于 TE 区间内的 eQTL variant，不等于证明 TE 导致基因表达变化；Both 表示两类关联证据同时存在，不是两次因果验证。克制且准确的表述，比强行拔高机制更贴合数据描述论文。
4. **说明别人能复用什么，不把正文写成操作手册。** 聚焦可独立使用的数据层、字段、关系及适用问题；界面只辅助说明访问。潜在用途应有数据能力支撑，但不要扩展成复杂的生物学发现案例。
5. **主动交代覆盖范围和限制。** 哪些来源、组织、TE 层级、匹配方式被纳入，哪些未覆盖、存在歧义或偏倚，都应清楚。不要用一个代表案例替代整体质量，也不要把未匹配解释成不重要。

以上是结合项目的写作判断。官方要求 Data Descriptor 聚焦方法、数据记录与技术验证，不加入一般 Results/Discussion；Usage Notes 也不是卖点、结论或完整案例研究的位置。[官方投稿指南](https://www.nature.com/sdata/submission-guidelines)。

## 写作时的自检

每个重要段落或图表，都问自己：它是在解释**数据怎样产生、包含什么、为何可靠、怎样复用**，还是只是在展示系统功能、强调“先进”，或讲超出证据的科学故事？后者应缩减、改写定位或移出这篇 Data Descriptor。

不需要为了“迎合”而隐藏不足或制造新颖性。更现实的增益是：让编辑迅速看懂文体适配，让审稿人能核实新增数据价值和质量，让读者能明确知道自己可以拿走什么。
