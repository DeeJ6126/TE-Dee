## 先建立一个整体思路

以下是**阅读导航，不是论文内容或额外期刊规定**。

### 写作前：先确定文章类型与共享对象

Data Descriptor 的主线是“数据如何产生、包含什么、质量怎样、别人如何取得并复用”，不是以新生物学结论为中心的传统研究论文。Article 则是另一类研究数据共享主题，不能把两者章节要求混用。先读范围，再决定文体。

### 写作中：让每个章节回答不同问题

| Data Descriptor 章节 | 读者需要知道什么 |
| --- | --- |
| Background & Summary | 为什么建立这份数据，相关背景是什么？ |
| Methods | 输入来自哪里，采集、清理、处理如何完成，能否复现？ |
| Data Records | 实际交付哪些文件，存在哪里，各字段和目录是什么？ |
| Technical Validation | 用哪些检查证明数据技术质量可靠？ |
| Usage Notes（可选） | 获取或处理时需要知道哪些技术事项？ |
| Data Availability / Code Availability | 到哪里取得数据和代码，有什么限制？ |

可选 Data Overview 只容纳少量概览，不是改名后的 Results/Discussion。验证质量的必要分析与追求新发现的一般分析，需要区分。章节完整顺序及声明位置见[详细指南](submission-guidelines.md)。

### 初次投稿：重点是材料完整可读

可以先用一份包含图表和说明的 PDF；同时准备能供审稿人匿名取得的数据及可访问的代码、适用表格和系统信息。不要把时间全花在旧模板排版上。附信与供审稿人查看的数据访问说明用途不同，不能混放。

### 返修与发表：交可编辑文件和稳定数据版本

返修需要源文件、独立完整图、逐项回复等；从第二轮起，数据存档与公开要求更严格，敏感数据另走适用的受控路线。持续更新的网站应与固定的受审数据版本区分。

详细初投、返修要求来自[投稿指南](submission-guidelines.md)，数据版本和共享要求来自[数据政策](data-policies.md)。

## 最容易混淆的地方

- 标题 110 **字符**包含空格；摘要建议 170 **英文单词**。不要按中文字符去套摘要词数。
- 八幅图、十张表是**建议**，不是绝对上限；图注 350 词则是明确限制。
- 首轮可提交 PDF，不等于返修也只交 PDF。
- 论文的开放获取许可，不等于第三方输入数据可任意再分发。
- 无自定义代码仍要代码可用性声明；二次人类数据仍须按检查表的适用分支核对。
- 网站 About 不要图注的设计选择，与论文要求为图表提供说明是两回事。
- 译文里的政策示例不是已替你作出的贡献、伦理、许可或利益冲突声明。

## 机器记录如何理解

[来源登记](../sources.json)和[下载记录](../download_manifest.json)是程序可读的证据文件，不修改字段名或哈希。`id` 为资料标识，`title` 为标题，`url` 为来源，`file` 为本地文件，`linked_from` 为发现下载链接的页面，`expected` 为检查标记；`fetched_at_utc` 是获取时间，`bytes` 是大小，`sha256` 是内容校验值，`status` 是 HTTP 状态，`content_type` 是文件类型。

原页面内部链接指向的其他政策没有全部下载或翻译；需要进一步核对时，从相应英文原页进入。本次译文不是法律、伦理审批或接收保证。
