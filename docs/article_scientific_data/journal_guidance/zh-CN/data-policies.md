# 数据政策（中文译文）

原文：[官网](https://www.nature.com/sdata/policies/data-policies)；[本地英文快照](../official_pages/data-policies.html)。快照日期：2026-09-02。

以下翻译正文，不含导航和页脚；非官方译文，以英文为准。中文“人类来源数据”不自动等于“敏感个人数据”，两者须区分。

Scientific Data 的主要文章类型 Data Descriptor 描述数据集。数据必须在投稿时向编辑和审稿人提供，并在最终发表时与科学界共享。本政策与 Springer Nature 的标准研究数据政策及 Research Data Alliance 的相关标准化工作要求相容。需要个别指导时可联系期刊。

## 数据类型与原始程度

期刊考虑生物、物理、环境、医学、社会、工程等各领域数据，但数据应适用于某种分析。原始文档、未标注图像或纯定性观察，只有在为机器读取和分析作出相应处理后才可能被考虑。

数据应保留足以支持领域惯例下复用的原始程度。多层级发布有时有利，例如蛋白质组同时提供原始质谱和加工后的肽段、蛋白层级数据；但若已有层级足以支持潜在用途，并不强制提供所有层级。

可以提交代码、模型、工作流和汇总表等补充信息，但强烈建议优先存入数据仓储，尤其**原始数据不应作为论文补充附件提交**。原始程度是否合适，由审稿人或负责编辑在数据效用检查中判断。

## 数据仓储

期刊要求发布与稿件关联的数据，但不自行托管数据，作者必须使用数据仓储。具体要求见[仓储指南](repositories.md)。一个 Data Descriptor 可以涉及多种数据和多个仓储，应采用适合实际用途的结构。

个人网站、实验室网站或非正式云平台通常不足以作为 Data Descriptor 的正式存档位置，除非自建平台符合期刊要求。原文对特别大型数据集给出例外，阈值写作 `>1 Tb`，原因是这类数据寻找合适仓储更困难。不要自行把这一例外理解为所有本地数据库都可免于存档。

## 初次投稿

第一轮评审必须允许审稿人通过 URL 顺畅、匿名地下载和检查数据。可使用最终仓储；如希望延迟公开或设置首轮暂缓公开，也可用临时云存储。

使用私有链接或访问码时，在 Data Records 中给出完整临时访问说明。敏感人类数据若需要访问控制，也必须提供符合审稿时限的匿名访问方式；可视敏感程度，在临时位置提供不敏感的代表性样本，或安排不泄露审稿人身份的特殊访问方式。

期刊虽记录审稿邀请和接受情况，但不能另行审核审稿人的资格、向作者提供审稿人姓名，或为每位审稿人分别分发密码。临时访问方法应写清楚，放在 Data Records 的临时说明或稿件前附的说明页中。

## 后续评审与发表

从第二轮起，数据必须公开，并存入符合政策的正式仓储。Article 的相关数据也须共享。

编辑、编委和审稿人会评估所选仓储是否合适，必要时可要求发表前另存其他仓储。期刊希望尽早处理这些问题，但直至最终接收前的任何阶段，都可能提出合规修改。

## 人类来源数据

该政策旨在支持不能完全公开的数据共享。“敏感人类数据”是指分享或使用可能使参与者或患者面临伤害风险的信息，不是所有人类来源的数据都属于此类。

最常见的考虑是匿名程度。部分匿名或未匿名的数据，应评估披露和使用可能造成的风险。可识别信息与宗教、种族、健康、性身份、政治观点等敏感字段结合时，风险尤其高。未成年人和其他脆弱群体的数据也可能风险更高。

**所有提交人类来源数据集的作者必须填写 Human Data Checklist，并作为 Related Manuscript file 随稿提交。**

### 常见共享方式

**完全开放：** 数据已充分匿名、重新识别风险极低，或者不含敏感字段；不需要使用控制；可以开放下载，并采用 CC BY、CC0 或等效开放许可。

**受控访问：** 数据并未充分匿名，或者敏感字段披露可能使参与者或患者面临风险。用户必须注册，可能需要验证身份，并通常记录姓名与机构；通过所有用户签署的数据使用协议（DUA）或其他合同规定使用限制。

极少数情况下，参与者可同意公开其可识别数据，但必须充分知晓风险、识别身份在科学上必要或不可避免，且没有分享其他敏感字段；否则应采用受控访问。

### 二次人类数据集

上述方式主要针对数据所有者首次公开此前不能下载的数据。由公共数据库已有数据派生的二次共享，通常不适用同样的人类数据共享要求，因为数据管理责任在原第三方。

但使用者必须遵守原所有者的条款，尤其检查是否有**再分发权**，以及 DUA 是否含禁止衍生或禁止披露条款。期刊不要求二次利用一律重新取得伦理审批，但原数据方或作者所在机构可能有此要求。

### 对开放和受控人类数据的检查

- 已取得参与者或患者同意，或者机构审查委员会（IRB）已批准豁免。豁免仅适用于采集时无法取得同意、完全匿名、非生物识别、来自非脆弱成年人的数据。
- 儿童和脆弱成年人的数据不能用该豁免共享，不论匿名程度或敏感性如何，都须取得适当家长、监护人或负责成年人的共享同意。
- IRB 或伦理委员会已经批准开展研究，**并批准共享数据**。

### 仅对受控访问数据的检查

首先检查为什么不能开放共享。原则是“尽可能开放，必要时才限制”。只有存在具体风险时才应增加限制。

风险取决于文件类型、直接标识符，例如基因组、姓名、面孔，以及可能联合缩小人群至可识别范围的间接标识符，例如位置、性别、医疗特征、职业。既可识别又含敏感字段的数据风险最高。编辑无法判断风险时，可能要求解释或扩大开放；若认为开放方式不足以保护个人，也可要求改用受控访问。

### 受控访问流程

建议控制限于注册、身份核验及主动签署或同意 DUA，而不是人工判断每个用户是否“适合”使用。

通常，所有能提供可核验身份且接受条款的用户都应获得访问，不应按研究问题、机构类型、国籍等与数据保护无关的因素筛选。因此，通过数据访问委员会逐人决定并非常规预期。

不能避免人工审核时，论文应说明所问问题和决策方式。编辑可能要求提供假设案例，解释哪些申请会通过或被拒绝。

### DUA 常见最低条款

措辞可以不同，但通常要求用户：

- 不直接或通过关联其他来源重新识别参与者。
- 不向未列名或未签约的人再分发；每位用户应按个人或团体签约并直接获取数据。
- 仅用于内部研究或分析；产出和衍生物不得违反不再分发规定，也不与参与者进行外部联系。这隐含禁止直接出售数据等商业使用，但不排除药物、工具开发等商业研发。
- 安全托管和管理数据，提供适当控制及培训。

可以包含责任说明、泄露应对、仅重申既有保护的知识产权通知、引用要求，以及 CC BY 等标准开放许可中已有的条款。

要求培训证明时，培训应能实际降低参与者风险，并应为预期的国际用户群体合理获得。

### 可能被要求修改或删除的条款

与保护个人无明显关系的限制可能被要求移除，例如主张衍生知识产权归属、要求发表前向数据方提交论文、要求共同署名或超出标准引用的归属、限制商业研发等。

### 使用限制与同意管理

向参与者承诺的用途限制，建议只针对泄露或识别身份等可能造成具体伤害的使用。除此以外，应请求允许在学术或商业环境中进行合法、安全的内部研究。

不建议设置“仅学术使用”“仅脑研究”等过细用途承诺，因为这些限制会增加合规负担，却未必影响参与者风险。

初始同意过于严格而妨碍安全共享时，建议重新取得同意，或在 IRB 认为安全合适时申请追溯豁免；后者仍仅适用于完全匿名、来自非脆弱成年人的数据。

## 数据保存

研究者、机构、期刊和仓储共同承担长期保存责任。作者必须承诺在 Data Descriptor 发表后，**至少五年**在自身实验室或机构服务器上保存数据。

若原仓储消失或数据丢失，期刊可要求重新上传到其他仓储并发表更正或更新。若作者移除公开数据，或将访问条件改为与论文不符，期刊可要求更正，极端情况下撤稿。

## 数据汇编

从已有文献提取少量数值或其他字段来构建二次汇编时，期刊不要求逐一向原作者申请许可，但应通过引用正确注明来源。必须确保字段准确，并在数据层面清楚提供来源文章的 DOI、URL 或等效标识。常见形式是一行一个数据点、单独一列记录来源。

该政策**不适用于整段文字、图像、视频等可能侵权的完整复制**。这类内容通常只有在取得许可，或原文采用 CC0、CC BY 等允许的许可时才能再分享。作者应向机构版权专业人员确认当地法律下允许的再分发方式。

除了在数据文件中列明来源，强烈建议在论文中引用原始工作，给予作者学术归属。例如可在 Methods 说明全部文献来源均已列在数据文件并在文中引用，然后列出编号。这是原政策的说明示例，不是替作者起草声明。

这类文献列表建议最多 500 项；更长列表受排版限制，但仍须在数据文件中保留全部来源。建议主要针对具有正式元数据的来源，例如带 DOI 的论文。

二次汇编不能在没有来源的情况下把记录标为 unpublished。汇编必须基于既有、可查见的来源；来源可为同行评审论文、预印本或其他材料，由编者根据适用性和可信度决定。

尚未在公开文档中记录的数据属于首次披露的数据，必须在 Data Descriptor 中说明采集方法，并在数据文件中标明是在本文中新报告的。创建这些数据的人通常应署名或得到正式致谢。

有可引用来源时，不应仅因为使用其数据，就把原始作者列为汇编论文作者；原则与综述或书章相同，要求的是引用归属，而非署名。若原作者积极参与了新工作，或属于全部数据首次公开的众包、公民科学项目，则另行判断，由项目负责人确定合适的认可方式。

新闻、纸质文献、专利或灰色文献中的事实也有类似考虑。既有正式新闻中的人类相关信息，即使涉及健康、政治或犯罪等敏感主题，若未披露新的个人信息，通常不归入本政策，但仍需谨慎处理。

社交媒体帖子、账号关联信息等通常属于人类数据，没有参与者同意通常不能索引或再发布；这与平台版权或条款是否允许是不同问题。即使公开可见，也可能被合理视为个人资料、通信或并非有意公开的内容。企业或官方账号的明确公开发布可能获例外，但界定可能困难。

分类广告、即时通信等交易或交流性质更强的材料，即使公开也很少获准再分享。非个人信息或汇总统计，例如帖子数量，通常可作为非敏感数据处理。

## 数据集更新

论文正文应只描述已完成项目和现有数据集，期刊不能预先评估未来才产生的数据，即便采用相同方法。

计划持续更新资源时，须把接受评审的**静态版本**存入适当仓储，在 Data Records 中说明，并以永久 DOI 引用；接收后不再修改该版本。

后续动态版本应在另外的位置托管，例如项目网站，并在 Usage Notes 中与正式记录版本区分。仓储可能支持使用新的或更新的 DOI 发布后续版本。新版本页面应说明与原版的差异，例如更新日志，并明确是在原版本同行评审后产生的。

不能为了增添新数据而追加修改论文，例如替换 DOI 或新增新版链接；纠错性质的文章或数据修订则遵循更正政策。

若使用投稿系统集成的 Figshare 代存方式，作者以后不会重新获得修改数据的管理员权限。这既与技术和资源限制有关，也符合评审后数据不应继续变动的原则，纠错除外。

需要持续管理权限时，可选择其他仓储；若仍使用 Figshare，可自行通过其公共网站注册提交，不必使用投稿系统代存，最终功能相同。

期刊欢迎描述重要数据集实质更新的新稿，尤其当达到新里程碑或采集方法明显变化时。新 Data Descriptor 须正式引用共同数据，并接受正常投稿评审。审稿人通常检查方法、验证或数据描述是否有足够变化，足以支持另发一篇。

## 数据引用

正文提及的所有外部仓储数据，包括主要输出及使用过的其他数据集，都须正式引用。已发表数据应同时引用数据集及相关研究论文。期刊工作人员在发表前检查并落实数据引用要求。格式见[投稿指南](submission-guidelines.md)。
