# Agent 与 Deep Think 的差异化发展方向

## 当前判断

Deep Think 已经可以覆盖大多数即时问答、站内导航、实体查询、序列查询、表达查询、图谱关系查询和轻量证据整合。继续让 Agent 和 Deep Think 都承担“普通问答”会造成重复维护、前端复杂度上升和用户选择成本增加。

因此，Agent 不应继续和 Deep Think 竞争短问答能力，而应发展成“可审计、可恢复、可导出的研究工作流”。

## Agent 更适合承担的能力

1. **长任务和异步研究运行**

   Agent 已经有 async run、worker、状态轮询和六阶段工作流。这个基础更适合处理耗时任务，例如跨多个 TE、多个疾病、多个文献主题的批量分析，而不是单个问题的快速回答。

2. **可恢复的多阶段工作流**

   Deep Think 适合一次性回答；Agent 应该允许用户看到每一步的输入、插件输出、证据是否充分、下一步为什么继续或停止。失败后也应该能从已完成阶段恢复，而不是整轮重来。

3. **证据审计和可解释决策**

   Agent 的优势应该是把 Graph、Literature、Literature Reading、Citation Resolver 的证据链拆开展示：哪些结论来自图谱，哪些来自文献摘要，哪些来自全文阅读，哪些只是低置信度推断。

4. **可导出的研究报告**

   Agent 可以输出结构化 Markdown、LaTeX、CSV 或 JSON 报告，包含问题、实体、插件链、证据表、引用、限制和结论。这类产物比普通聊天回答更有价值，也更符合六阶段工作流的定位。

5. **批量任务和比较任务**

   Agent 适合处理“比较多个 TE 与某类疾病的关系强度”“批量检查一组 TE 的表达与基因组位置”“生成某个 TE family 的证据矩阵”等任务。这些任务需要队列、进度、失败记录和结果汇总，Deep Think 不应承担。

6. **用户可检查的计划执行**

   Agent 应该在正式执行前生成计划，让用户确认插件链、实体范围、数据源和输出格式。这样 Agent 的定位会更接近研究助理，而不是另一个聊天入口。

## 建议边界

- Deep Think：即时问答、站内入口定位、简单图谱查询、单实体序列/位置/表达/关系查询、轻量文献支持。
- Agent：长任务、批量任务、多实体比较、机制研究、证据审计、报告生成、可恢复异步工作流。

## 后续优化优先级

1. 将 Agent 的输出目标从“聊天答案”升级为“研究任务产物”。
2. 给 Agent 增加任务模板，例如机制综述、关系强度排行、TE family 对比、文献证据表。
3. 将 Agent 的每个阶段状态和证据包持久化，支持失败恢复和结果复查。
4. 让 Agent 的 Writing 阶段基于结构化报告模板，而不是把大量证据一次性塞给 LLM 写长答案。
5. 保持 Deep Think 作为全站默认问答入口，避免三套问答系统继续分裂。
