# TE-KG 首页改进计划

本文记录对其他知识图谱 / 生物数据库首页的参考观察，并给出 TE-KG 首页改进方向。本文只做规划，不改实现。

## 参考页面

### HALD / HALDxAI 系列

参考链接：

- HALD: https://bis.zju.edu.cn/hald/
- BIS 资源页中的 HALDxAI 条目: https://bis.zju.edu.cn/

可借鉴点：

- 首页直接提供搜索入口。
- 搜索支持实体类型过滤。
- 首页给出示例查询，例如基因、疾病等。
- About 区域用数据规模说明数据库可信度：实体数、关系数、文献来源数量。
- 页面结构简单，但用户一进入就知道“能搜什么、数据有多少、入口在哪里”。

对 TE-KG 的启发：

- 首页不应只是空白入口页，应把搜索、示例、数据规模和核心功能放到第一屏或第二屏。
- TE-KG 可以突出 TE、Disease、Function、Paper / Evidence 等实体和关系规模。

### Hetionet

参考链接：

- https://het.io/

可借鉴点：

- 首页文案非常直接：说明它是整合多数据库的 biomedical knowledge network。
- 明确展示数据规模：节点数、节点类型、关系数、关系类型。
- 导航入口清晰：About、Explore、Studies、Software、Media。

对 TE-KG 的启发：

- 首页应该有一句非常明确的定位：
  - “TE-KG is a transposable element-centered biomedical knowledge graph...”
- 应展示核心统计：
  - TE 数量
  - Disease 数量
  - Function 数量
  - BIO_RELATION 数量
  - PubMed evidence 数量
  - journal metric coverage

### ADiKA

参考链接：

- https://www.adika-ai.org/

可借鉴点：

- 首页顶部使用大规模数据卡片展示：实体数、关系数、数据源数、实体类型。
- 有 Platform Highlights，说明知识整合、AI/reasoning、federated evaluation 等能力。
- 有 Interactive Knowledge Graph 区块，让用户预期可以探索图谱。
- 有 Publications / Research 区块，增强学术可信度。

对 TE-KG 的启发：

- 首页可以分成“数据规模”、“核心能力”、“探索入口”、“证据支持”、“文档/引用”几个区块。
- 不需要做很营销化的页面，但需要更像一个成熟数据库平台，而不是临时 demo。

### Bio-Graph

参考链接：

- https://bio-graph.io/

可借鉴点：

- 首页强调从 fragmented data 到 actionable graph。
- 用 Use Cases 解释平台能解决什么问题。
- 用 Architecture / Layers 展示平台由哪些层组成：
  - knowledge graph
  - enrichment agents
  - prioritization / scoring
- 强调 provenance、explainability、evidence。

对 TE-KG 的启发：

- TE-KG 首页可以突出“证据可追踪”：
  - 每条边可查看 PMID evidence table。
  - 每条关系有 support_pmid_count、IF/JCR evidence support。
- 首页应说明 TE-KG 不只是可视化图谱，而是带文献证据和数据库来源的探索工具。

### Open Targets / PrimeKG

参考链接：

- Open Targets Platform: https://platform.opentargets.org/
- Open Targets evidence docs: https://platform-docs.opentargets.org/evidence
- PrimeKG registry: https://kghub.org/kg-registry/resource/primekg/primekg.html

可借鉴点：

- Open Targets 强调 target-disease evidence 和按数据源组织证据。
- PrimeKG 强调跨多个生物尺度整合资源。
- 这类平台的首页通常不只提供图谱入口，还强调：
  - evidence source
  - scoring / ranking
  - API / downloadable data
  - documentation

对 TE-KG 的启发：

- 首页可以引导用户理解 evidence support，不把 IF 叫 confidence。
- 可以提供“数据来源 / 证据模型 / API / 下载”入口。

## TE-KG 首页建议结构

### 1. 第一屏：数据库定位 + 搜索入口 + 动态背景

目标：

- 让用户一进入首页就知道 TE-KG 是什么。
- 直接开始搜索 TE、Disease、Function 或 relation evidence。

建议内容：

- 标题：`TE-KG`
- 副标题：`A transposable element-centered biomedical knowledge graph with literature evidence support.`
- 主搜索框：
  - placeholder: `Search L1HS, LINE1, Alu, SVA, disease, function...`
- 示例按钮：
  - `L1HS`
  - `LINE1`
  - `AluJb`
  - `SVA`
  - `Aging`
- 主按钮：
  - `Explore Graph`
  - `Browse Taxonomy`
- 背景：
  - 不做营销式大图。
  - 用轻量 Canvas/SVG 动态图谱或 TE mechanism 背景。
  - 保持安静、科研工具感。

给母智能体的简短提示词：

```text
请为 TE-KG home 页面设计并实现第一屏：数据库定位、主搜索框、示例查询按钮、Explore Graph / Browse Taxonomy 入口，以及轻量 TE/graph 动态背景。保持科研数据库风格，不做营销落地页。先创建 active plan，完成后验证并归档。
```

### 2. 数据规模统计卡片

目标：

- 像 HALD、Hetionet、ADiKA 一样，用数字建立可信度。

建议统计：

- TE entities
- Disease entities
- Function entities
- BIO_RELATION relationships
- PubMed evidence records
- Paper nodes
- Journal metric coverage
- Taxonomy nodes / edges

实现建议：

- 优先使用已有 API 或生成的 `docs/generated/` / `data/processed/` 统计。
- 如果缺 API，先做静态 generated summary，不要在首页直接跑重查询。

给母智能体的简短提示词：

```text
请为 home 页面增加数据规模统计区块。先调查现有 API/generated docs 是否已有 TE、Disease、Function、BIO_RELATION、Paper、PubMed evidence、journal metric coverage、taxonomy node/edge 统计。优先复用现有统计，不要在首页引入重查询。实现前先建 active plan。
```

### 3. 核心能力入口卡片

目标：

- 让首页能说明 TE-KG 能做什么，而不只是“点进去再说”。

建议入口：

- `Explore TE Graph`
  - 进入 `preview.php`
  - 说明支持 Jump / Expand / evidence table。
- `Browse TE Taxonomy`
  - 进入 taxonomy / tree view。
- `Expression Atlas`
  - 进入 `expression.php`。
- `Path Finder`
  - 进入 `path_finder.php`。
- `Search Database`
  - 进入全站 search / browse。

给母智能体的简短提示词：

```text
请为 home 页面增加核心能力入口卡片：Explore TE Graph、Browse TE Taxonomy、Expression Atlas、Path Finder、Search Database。每张卡片要说明用户能做什么，并链接到现有页面。只改 home 相关前端，不改业务逻辑。
```

### 4. Evidence Support 展示区

目标：

- 把最近完成的 evidence support 工作展示出来。
- 让用户知道边不是“空关系”，而是有 PMID / journal metric 支持。

建议内容：

- 一个示意边卡：
  - PMID count
  - IF mean / max
  - JCR Q1/Q2 count
  - year range
- 文案强调：
  - `Evidence support, not confidence.`
  - 每条边可查看 PubMed evidence table。
- 可放一个小型静态 mock，不需要真实加载图谱。

给母智能体的简短提示词：

```text
请在 home 页面增加 Evidence Support 区块，展示 TE-KG 的边证据能力：PMID count、journal metric coverage、IF/JCR summary、PubMed evidence table。文案必须避免把 IF 称为 confidence。优先做静态示意，不要在首页加载完整 G6 图谱。
```

### 5. 数据来源与可追溯性区块

目标：

- 说明 TE-KG 的数据从哪里来、如何追溯。

建议内容：

- PubMed metadata
- Neo4j `tekg3`
- TE taxonomy / rmsk_repbase
- journal metrics source: `impact_factor_package_2025`
- evidence_records 不含 abstract
- 缺失 IF 保持 null，不猜测

给母智能体的简短提示词：

```text
请为 home 页面增加 Data Sources & Provenance 区块。说明 TE-KG 使用 PubMed metadata、Neo4j tekg3、TE taxonomy、journal metrics v1 和 relation evidence support。强调缺失 IF 不猜测，IF 是 journal metric 不是 confidence。
```

### 6. Quick Start / Example Workflows

目标：

- 降低用户进入门槛。
- 告诉用户从首页开始应该点什么。

建议 workflow：

1. Search `L1HS`
2. Open TE graph
3. Click an edge
4. Inspect PubMed evidence
5. Export edge evidence CSV

也可以增加：

- Browse taxonomy → expand to L1HS
- Search disease/function → inspect related TE
- Open expression page → select TE expression profile

给母智能体的简短提示词：

```text
请在 home 页面增加 Quick Start 区块，用 3-5 个短步骤说明如何从 L1HS 示例开始探索图谱、查看边证据、导出 PubMed evidence CSV。不要写长说明，做成可扫描的步骤卡片。
```

### 7. 更新日志 / 数据版本区块

目标：

- 让用户知道数据库不是静态黑盒。

建议内容：

- 当前 Neo4j target: `tekg3`
- PubMed metadata records: 2308
- Paper enrichment date / import tag
- relation aggregation import tag
- G6 evidence UX status
- taxonomy parser fix status

给母智能体的简短提示词：

```text
请为 home 页面增加 Data Version / Release Notes 区块，展示当前 tekg3、PubMed metadata 2308 records、journal metrics v1、relation support aggregation、G6 evidence UX 等状态。数据来自已有 docs/RELIABILITY.md 或 generated summary，不要在首页跑重查询。
```

## 推荐实施顺序

建议不要一次性做成大杂烩。按以下顺序：

1. 第一屏搜索入口 + 动态背景。
2. 数据规模统计卡片。
3. 核心能力入口卡片。
4. Evidence Support 展示区。
5. 数据来源与可追溯性区块。
6. Quick Start。
7. 数据版本 / Release Notes。

如果只做一个 v1，建议包含：

- 第一屏
- 搜索入口
- 示例查询
- 数据规模统计
- 核心能力入口
- Evidence Support 简介

## 首页设计原则

- 首页应该像科研数据库门户，不像商业 SaaS 落地页。
- 使用真实数据规模和真实入口，不写空泛宣传语。
- 不在首页加载完整 G6，避免性能风险。
- 动画应轻量，作为背景或微交互，不抢搜索入口。
- 文字要短，用户能快速知道：
  - TE-KG 是什么；
  - 能搜什么；
  - 数据有多少；
  - 怎么进入图谱；
  - 证据怎么追溯。
